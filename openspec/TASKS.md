# TASKS: план реализации MVP на 5 дней

Исполнитель кода — агент (работает по RULES). Задачи автора отмечены **[Никита]**. В скобках у раздела задачи — разделы спецификаций, на которые она опирается.

## Правила использования файла

- Файл **только для чтения**. Агент его не изменяет и не отмечает в нём выполнение. Прогресс ведётся только в файлах `openspec/tasks/` (RULES, раздел 3).
- Номера задач (1.1, 2.3 и т.д.) нужны только для ссылок. **В именах файлов номера не используются.**
- Файл задачи называется `openspec/tasks/YYYY-MM-DD-<имя>.md`, где `<имя>` указано у задачи в поле «Имя». Пример: задача 1.1 → `openspec/tasks/2026-11-03-project-setup.md`.

## Порядок и логика

1. Сначала каркас и токены, чтобы всё последующее собиралось в одном стиле.
2. Затем ядро логики (состояние, переходы, таймеры) без интерфейса: это самая рискованная часть, и всё остальное от неё зависит.
3. Потом интерфейс экрана приложения поверх готовой логики.
4. Затем демо-вкладка, мобильная версия, анимации и слайдер.
5. Последний день: слайды, проверка, доступность, публикация.

## Параллельные задачи автора

- **[Никита]** Тестовые данные (аудитории и заполненность ИРиТ и ИнЭУ). Нужны к началу Дня 2 (FEATURES 11).
- **[Никита]** Дизайн слайдов в стиле приложения и конвертация в HTML. Идёт параллельно с Дня 1, готовность к началу Дня 5 (FEATURES 3).
- **[Никита]** Решить до Дня 3: как студент попадает на экран аудитории из списка (в FEATURES 10 описано только содержимое экрана).

## День 1. Фундамент и каркас сайта

- **1.1 Проект.** Имя: `project-setup`. Инициализация React + Vite, структура папок, минимум зависимостей (PRODUCT 7, RULES 4, 6).
- **1.2 Токены и глобальные стили.** Имя: `design-tokens`. Цвета, типографика, отступы, радиусы, длительности и кривые анимаций, `color-scheme: dark`, сброс стилей (DESIGN 2-4, 7.1, 9).
- **1.3 Каркас сайта.** Имя: `site-shell`. Шапка с вкладками «Презентация» и «Демонстрация», подвал со ссылкой на GitHub, брейкпоинты 640 и 1024 px (FEATURES 2, DESIGN 6).
- **1.4 Раскладка демо.** Имя: `demo-layout`. Две колонки и рамка телефона с вырезом, без логики (DESIGN 5, 6.1).
- **1.5 [Никита] Тестовые данные.** Подготовить список аудиторий и заполненность.

**Готово, когда:** проект собирается, вкладки переключаются, на «Демонстрации» видна рамка телефона.

## День 2. Данные и логика

- **2.1 Модель данных.** Имя: `data-model`. Аудитория (название, вуз, этаж, вместимость), студенты-сессии user1-3, загрузка тестовых данных (FEATURES 4.2, 11).
- **2.2 Хранилище.** Имя: `state-store`. Общее состояние (люди, режим, главный, заявки) и состояние каждой сессии (вуз, свёрнутые блоки, поиск) (FEATURES 4.2, 6, 8).
- **2.3 Действия и переходы.** Имя: `actions-transitions`. Занять в двух режимах, записаться, подать заявку, принять и отклонить, покинуть. Смена главного, правило одной аудитории, лимит 5/5 (FEATURES 6-8).
- **2.4 Движок времени.** Имя: `time-engine`. Единый ход времени с множителем x1/x5/x200, таймеры 5 минут, 2 часа и 30 минут, автоисключение, работа таймеров у невыбранных сессий (FEATURES 4.3, 9).
- **2.5 Выборки.** Имя: `selectors`. Группировка по блокам, сортировка (этаж, затем алфавит), фильтр поиска (FEATURES 5.3, 5.4, 5.6).
- **2.6 Проверка логики.** Имя: `logic-check`. Прогон сценариев по таблице переходов (FEATURES 7) через временную отладочную страницу или консоль.

**Готово, когда:** все переходы из таблицы FEATURES 7 и все таймеры работают корректно, в том числе на x200.

## День 3. Экран приложения

- **3.1 Шапка приложения.** Имя: `app-header`. Название и выпадающий список вузов (FEATURES 5.1).
- **3.2 Поиск и блоки.** Имя: `room-list`. Сворачиваемые блоки «Свободное», «Доступное», «Занято» (последний свёрнут по умолчанию), строки с кружком статуса, названием, счётчиком и кнопкой (FEATURES 5.2, 5.3, DESIGN 2.2, 5).
- **3.3 Прокрутка.** Имя: `list-scroll`. Контейнер на 5,5 строки, скрытый скроллбар, маска затухания (FEATURES 5.5).
- **3.4 Занятие.** Имя: `occupy-flow`. Диалог выбора режима и плашка «Вы работаете в…» с кнопкой «Покинуть» (FEATURES 5.7, 7).
- **3.5 Экран аудитории.** Имя: `room-screen`. Название, статус, счётчик, заявки только для главного, «Покинуть», индикатор таймера на 5 минут (FEATURES 8-10).
- **3.6 Диалог через 2 часа.** Имя: `stay-dialog`. «Вы до сих пор находитесь в…?» с двумя вариантами (FEATURES 9).

**Готово, когда:** в одной сессии можно пройти весь сценарий: найти аудиторию, занять, получить заявку, принять, выйти.

## День 4. Демо, мобильная версия, слайдер, анимации

- **4.1 Демо-вкладка.** Имя: `demo-sessions`. Переключатель сессий user1-3 с отдельным состоянием каждой и переключатель скорости x1/x5/x200 (FEATURES 4).
- **4.2 Мобильная версия.** Имя: `mobile-demo`. Демонстрация на весь экран без рамки телефона, панель демонстрации (нижняя панель), `100dvh`, safe-area (DESIGN 6.3).
- **4.3 Слайдер.** Имя: `slider`. Стрелки, свайп, клавиатура, вписывание слайда с сохранением соотношения сторон. До готовых слайдов используются заглушки с текстом из базы презентации (FEATURES 3, DESIGN 6).
- **4.4 Анимации.** Имя: `animations`. По списку DESIGN 7.2 в таком порядке: смена статуса и перестановка строк, сворачивание блоков, плашка и диалоги, заявки, вкладки и слайдер, остальное. Учёт `prefers-reduced-motion` (DESIGN 7).

**Готово, когда:** три сессии работают с общим состоянием, демо удобно на телефоне, ключевые анимации на месте.

## День 5. Слайды, проверка, публикация

- **5.1 Слайды.** Имя: `slides-embed`. Встроить готовую HTML-вёрстку вместо заглушек (FEATURES 3).
- **5.2 Доступность.** Имя: `accessibility`. Фокус, `aria-expanded`, `aria-live`, контраст, работа с клавиатуры (DESIGN 8).
- **5.3 Сквозная проверка.** Имя: `e2e-check`. Сценарии через все три сессии и оба вуза, таймеры на x200, поиск, мобильная версия и разные браузеры.
- **5.4 Исправления.** Имя: `final-fixes`. Правки по итогам проверки, финальная сборка без ошибок.
- **5.5 [Никита] Публикация.** README с инструкцией локального запуска, видео демонстрации для слайда MVP, размещение на GitHub.

**Готово, когда:** MVP открывается и по ссылке, и локально, слайды встроены, видео записано.

## Приоритеты при нехватке времени

1. **Обязательно:** статусы, занятие, запись, выход, общее состояние трёх сессий, сайт с обеими вкладками.
2. **Важно:** таймеры, заявки и главный, переключатель скорости, мобильная версия.
3. **Можно урезать:** анимации из нижней части списка DESIGN 7.2, маска затухания, первая загрузка с эффектом.
