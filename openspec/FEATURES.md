# FEATURES: функционал MVP

Подробное описание поведения MVP. Дополняет PRODUCT.

## 1. Общие положения

- MVP — веб-демонстрация приложения «Коворкинги» в УрФУ.Учёба.
- Вместимость у каждой аудитории своя и задаётся в данных автора. Заполненность отображается счётчиком «людей внутри / вместимость», например `2/6`.
- Бэкенда нет. Всё состояние хранится в памяти клиента и сбрасывается при перезагрузке страницы.
- Список участников аудитории (имя, время присоединения и время окончания) видят студенты, находящиеся в этой аудитории. Студентам вне аудитории список скрыт. Администрация видит список всех студентов в любой аудитории (вне MVP).

## 2. Сайт

Шапка: название «УрФУ.Коворкинги» и две вкладки: «Презентация» и «Демонстрация».
Подвал: «design & idea by Nikita Shvedov». Имя автора в подвале — ссылка на профиль GitHub: https://github.com/qpikzz.

Сайт адаптивен. На мобильных устройствах вкладка «Демонстрация» показывает приложение на весь экран, без рамки телефона (подробности в DESIGN).

## 3. Вкладка «Презентация»

- Слайдер со стрелками «назад» и «вперёд».
- Содержание слайдов — из подготовленной текстовой базы презентации.
- Дизайн слайдов делается отдельно и предоставляется автором в виде готовой HTML-вёрстки, которая встраивается на сайт.

## 4. Вкладка «Демонстрация»

### 4.1. Состав

- Текст: «Получай актуальную информацию о доступности коворкингов не заглядывая внутрь».
- Переключатель сессий: **user1, user2, user3**.
- Переключатель скорости времени: **x1, x5, x200**.
- Макет телефона с экраном приложения.

### 4.2. Сессии

Каждая сессия — отдельный студент со своим именем в формате «Имя И.» (например, «Никита И.»).

Своё у каждой сессии:
- выбранный вуз;
- свёрнутые и развёрнутые блоки списка;
- текст в строке поиска.

Общее для всех сессий:
- заполненность аудиторий и их статусы;
- главные в аудиториях и заявки на присоединение;
- все таймеры.

Если действие совершено в одной сессии, оно сразу отражается в остальных. Например, если user1 занимает I101 и пользователь переключается на user2, I101 в сессии user2 отображается как занятая.

### 4.3. Скорость времени

- Переключатель x1 / x5 / x200 ускоряет все таймеры и виртуальные часы статус-бара (см. раздел 9).
- Один переключатель на всё приложение, не на сессию.
- По умолчанию x1 (без ускорения).
- Часы статус-бара телефона — виртуальные. При загрузке страницы они показывают текущее время устройства в его часовом поясе.
- Дальше часы идут по единому ходу времени приложения с учётом множителя: на x5 и x200 обгоняют настоящее время.
- Часы общие для всех сессий и не зависят от выбранной сессии.
- При смене скорости часы продолжают идти с текущего значения, без скачка.
- Перезагрузка страницы сбрасывает состояние: часы снова берут время устройства.
- Формат часов — 24 часа, ЧЧ:ММ, без секунд.

## 5. Экран «Коворкинги»

### 5.1. Шапка

- Название «УрФУ.Коворкинги».
- Справа от названия — выпадающий список вузов. На тесте: **ИРиТ** и **ИнЭУ**.
- При выборе вуза показываются аудитории этого вуза.

### 5.2. Заголовок и поиск

- Заголовок «Коворкинги».
- Под ним строка поиска, перед блоками.

### 5.3. Блоки

Аудитории разделены на три блока в таком порядке:

1. **Свободное**
2. **Доступное**
3. **Занято**

Каждый блок — сворачиваемый заголовок, как в Obsidian. Можно свернуть и развернуть любой блок.
Блок «Занято» по умолчанию свёрнут.

Строка аудитории: название, счётчик `x/вместимость`, кнопка действия.

| Блок | Кнопка |
|---|---|
| Свободное | «Занять» |
| Доступное | «Записаться» |
| Занято | «Присоединиться» |

### 5.4. Сортировка

Сортировка одинакова во всех блоках:

1. По этажу. Этаж определяется первой цифрой номера аудитории (K115 — 1 этаж, K204 — 2 этаж). Сначала 1 этаж, затем 2 и далее.
2. Внутри этажа по алфавиту.

### 5.5. Прокрутка

- Прокрутка двухуровневая: экран приложения и блоки списка.
- Статус-бар и шапка приложения с названием и списком вузов закреплены сверху. Всё, что ниже (заголовок «Коворкинги», поиск и блоки), прокручивается как единое целое, если не помещается по высоте экрана.
- В блоке показывается 5-6 аудиторий, остальные доступны прокруткой.
- Полоса прокрутки скрыта: `scrollbar-width: none` и `::-webkit-scrollbar { display: none }` при `overflow-y: auto`.
- Последняя видимая аудитория показывается наполовину, чтобы было понятно, что список можно листать.
- Реализация: высота контейнера блока равна 5,5 высоты строки. Если аудиторий в блоке шесть и меньше, высота подстраивается под содержимое без половинной строки, прокрутки в блоке нет.
- Вложенная прокрутка: когда внутренний список блока доскроллен до конца, прокрутка продолжается во внешней области экрана. У блоков `overscroll-behavior: auto`, у внешнего экрана — `overscroll-behavior: contain`, чтобы страница вокруг телефона не прокручивалась вместе с ним.
- Дополнительно: лёгкое затухание у нижнего края контейнера, которое исчезает, когда список долистан до конца. Затухание показывается только пока есть куда прокручивать; состояние обновляется по событию `scroll` (passive) и через `ResizeObserver`.
- Клавиатура: прокручиваемые контейнеры получают `tabindex="0"` и `aria-label`, прокручиваются стрелками, кольцо фокуса видимое по DESIGN.
- Мобильная версия без рамки: высота `100dvh`, прокручивается только контейнер приложения, страница вокруг не прокручивается.
- Масштабирование рамки телефона: прокручиваемый контейнер имеет заданную высоту в логических пикселях, обёртка занимает масштабированный размер, колесо и тач работают внутри масштабированного экрана.
- Прокрутка без анимации по тику таймера, без `scroll-snap` и без `scroll-behavior: smooth`.

### 5.6. Поиск

- Строка поиска фильтрует аудитории по названию.
- При вводе скрываются все аудитории, которые не подходят под запрос.
- Если в блоке не осталось подходящих аудиторий, блок скрывается полностью.
- Пример: при вводе `K115` отображается только блок, в котором находится K115, и в нём одна эта аудитория.
- Поиск работает по всем блокам, включая «Занято».

### 5.7. Плашка текущей аудитории

Пока студент работает в аудитории, в верхней части интерфейса отображается плашка: «Вы работаете в I101 [Покинуть]».

## 6. Статусы

| Статус | Что значит | Как войти |
|---|---|---|
| Свободное | Внутри никого нет | Нажать «Занять» |
| Доступное | Аудитория занята в режиме «Оставить доступным», внутри есть люди | «Записаться», без подтверждения |
| Занято | Аудитория занята в режиме «Занять полностью» | «Присоединиться», с подтверждением главного |

Студент может работать только в одной аудитории одновременно.
Записаться и присоединиться нельзя, когда людей в аудитории столько, какова её вместимость.

## 7. Действия и переходы

| Действие / событие | Было | Стало |
|---|---|---|
| «Занять» → «Оставить доступным» | Свободное | Доступное, 1 человек, студент становится главным |
| «Занять» → «Занять полностью» | Свободное | Занято сразу, 1 человек, студент становится главным, запускается таймер на 5 минут |
| «Записаться» | Доступное | Доступное, +1 человек |
| Заявка принята главным | Занято | Занято, +1 человек |
| Заявка отклонена главным | Занято | без изменений, заявка снимается |
| Конец таймера на 5 минут, внутри 2 и более человек | Занято | Занято сохраняется |
| Конец таймера на 5 минут, внутри менее 2 человек | Занято | Доступное |
| Студент покинул аудиторию или исключён, внутри остались люди | любой | статус сохраняется, счётчик уменьшается |
| Студент покинул аудиторию или исключён, внутри никого | любой | Свободное |

## 8. Главный в аудитории и заявки

### 8.1. Главный

- Главный — студент, который первым занял аудиторию.
- Для заранее заполненных аудиторий главный — участник с самым ранним `joinedAt`.
- Если главный покидает аудиторию или исключён, главным становится студент, присоединившийся вторым (следующий по `joinedAt`). Далее по порядку присоединения.

### 8.2. Заявки на присоединение

- В блоке «Занято» студент нажимает «Присоединиться» и тем самым отправляет заявку главному.
- Главный видит заявки на экране аудитории (раздел 10) и для каждой выбирает «принять» или «отклонить».
- Только главный может принимать и отклонять заявки.
- Если главный меняется, неразобранные заявки переходят новому главному.

## 9. Таймеры и сессии участников

Все таймеры и времена сессий идут по виртуальному времени с учётом переключателя скорости (раздел 4.3). Виртуальные часы статус-бара идут по тому же времени: пока таймер 5 минут отсчитывает 5 виртуальных минут, часы продвигаются на те же 5 минут; время сессий участников и продление также совпадают с часами. Таймеры, сессии и часы общие для всех сессий, не зависят от выбранной сессии и сбрасываются при перезагрузке страницы.

| Таймер | Запуск | По окончании |
|---|---|---|
| 5 минут | «Занять полностью» | Если внутри 2 и более человек, статус «Занято» сохраняется, иначе аудитория переходит в «Доступное» |
| 2 часа | С момента присоединения участника | Если участник не продлил сессию, он автоматически покидает аудиторию |

### Сессии участников

- У каждого участника в аудитории своя сессия: время присоединения `joinedAt` и время окончания `endsAt = joinedAt + 2 часа`.
- Начало сессии — момент присоединения именно этого человека, а не первого участника в аудитории.
- Все времена (присоединение, окончание, остаток, таймеры) считаются по виртуальным часам (раздел 4.3). Реального времени в логике сессий нет.
- Действие «Продлить» заменяет прежний вопрос о том, находится ли студент в аудитории. Продление увеличивает `endsAt` на 2 часа; `joinedAt` не меняется, участник не отключается, сессия не сбрасывается.
- «Продлить» доступно участнику за 30 минут до `endsAt` и до самого `endsAt`. После продления действие снова становится доступно за 30 минут до нового `endsAt`.
- Если участник не продлил сессию до `endsAt`, он автоматически покидает аудиторию.
- Правила сессии и автоматического выхода одинаковы для студентов и для участников-заглушек.

## 10. Экран аудитории

Экран отображает данные аудитории, в которой работает студент:

- название аудитории (например, K103);
- статус (например, «Занято»);
- количество людей в формате «людей внутри / вместимость»;
- заявки на присоединение: список студентов в формате «Имя И.» с кнопками «принять» и «отклонить». Раздел виден только главному;
- кнопка «Покинуть».

У студента, который не является главным, раздела заявок нет.

## 11. Тестовые данные

- Вузы: ИРиТ, ИнЭУ.
- Список аудиторий каждого вуза, их вместимость и начальная заполненность задаются автором вручную. Данные автора не изменяются.
- Для каждой аудитории с начальной заполненностью n при загрузке страницы один раз генерируются n участников-заглушек. После перезагрузки страницы участники генерируются заново.
- Имена заглушек имеют формат «Имя Ф.»: имя из пула в отдельном файле данных и первая буква фамилии с точкой. Пул примерно наполовину состоит из русских имён, остальные — в основном азиатские и ближневосточные имена, записанные кириллицей. Первая буква фамилии — случайная буква кириллицы, кроме Ъ, Ы, Ь, Й.
- Имена внутри одной аудитории не повторяются и не совпадают с именами сессий user1, user2, user3.
- `joinedAt` каждой заглушки — случайный момент за последние 0-115 минут по виртуальным часам; `endsAt` при этом обязательно находится в будущем.
- Заглушки живут по тем же правилам сессии и автоматического выхода. Отличие: в момент появления окна продления (за 30 минут до `endsAt`) заглушка с вероятностью 45% продлевает сессию на 2 часа, как при действии «Продлить», иначе уходит по окончании. Решение принимается один раз на каждый цикл сессии. Если окно продления уже наступило к моменту загрузки, решение принимается сразу.
- Заглушки учитываются в счётчиках, статусах и выборе главного. Когда уходит последний участник, аудитория становится «Свободное».
